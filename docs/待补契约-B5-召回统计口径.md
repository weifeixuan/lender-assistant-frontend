# 待补契约 B5：召回统计口径

- 状态：待后端确认
- 发现于：2026-10-29 前端联调自检
- 相关：后端 `docs/阶段6_后端接口补充需求.md`（B3 `QaSourceResponse`）

## 现象

对话页「检索过程」侧栏第①段「双通道召回」需要展示本轮各通道的召回条数，
但现有契约只有 `sources` 明细（B3），没有原始召回总数：

- `QaSourceResponse.vectorDistance` 仅在该切片被向量通道命中时有值；
- `QaSourceResponse.keywordHits` 仅在关键词通道命中时大于 0；
- 因此前端只能按「本轮送入上下文的 N 条来源」统计，无法知道向量通道召回 M1 条、关键词通道召回 M2 条后经 RRF 融合截断到 N 条。

当前界面已标注统计口径为「统计范围为本轮送入上下文的 N 条来源」，不构成错误展示，但信息不完整。

## 建议字段

`done` 事件（`QaDoneResponse`）新增可选字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `vectorRecallCount` | number | 向量通道原始召回条数（RRF 之前） |
| `keywordRecallCount` | number | 关键词通道原始召回条数（RRF 之前） |
| `fusedCount` | number | 两通道融合去重后的候选条数（RRF 输入） |

字段缺失时前端回落到当前口径（按 `sources.length` 统计），保持向后兼容。

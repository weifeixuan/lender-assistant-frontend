# ADR-0001 前端独立仓库与契约镜像

- 状态：已采纳
- 日期：2026-10-29

## 背景

知识库前端需要文档管理与知识库对话两页，与后端 `lender-assistant` 同期开发。
最初曾把前端放在后端仓库的 `frontend/` 子目录，构建、依赖与提交历史都和 Java 服务绑在一起。

## 决策

1. 前端作为独立仓库放在 `E:\project\lender-assistant-frontend`，与后端 `E:\project\lender-assistant` 同级，前后端分离、各自独立构建与部署。
2. 后端接口契约只在 `src/api/types.ts` 镜像一次，其他文件不得私自定义后端字段类型。
3. 两侧的对应关系写死在文档里而非工具里：需求口径见后端 `docs/阶段6_前端PRD.md`，接口补充见后端 `docs/阶段6_后端接口补充需求.md`，实现约束见本仓库 `AGENTS.md`。

## 理由

- 前端与后端的构建工具链、依赖安装、发布节奏互不相干，放在同一仓库会让两边的 `npm` / `maven` 目录互相干扰。
- 契约集中一处，后端改字段时只需要改一个文件，避免多处漂移；SSE 与普通接口的差异也能在这一层收敛。
- 独立仓库便于后续单独接入 CI 与静态部署，不需要为前端配置后端的 Maven 生命周期。

## 影响

- 跨仓库引用文档用相对路径（`../lender-assistant/docs/...`），两台机器上目录结构需保持一致。
- 契约变更必须同时修改后端 VO 与本仓库 `src/api/types.ts`，`npm run typecheck` 会暴露漏改的字段。

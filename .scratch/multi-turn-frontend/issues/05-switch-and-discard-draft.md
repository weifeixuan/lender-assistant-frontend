# 05: 切换会话与草稿丢弃

**What to build:** 用户点击另一条会话时，上一个会话的流式请求被中止，旧正文与来源立即清空，随后加载目标会话历史；点击当前会话不重复加载。用户从草稿态切到已有会话时，草稿被丢弃且列表不变。从会话点击「新对话」也先中止流式再进入草稿。切换过程中不允许出现「旧会话内容 + 新会话标题」的串台状态。

**Blocked by:** 03 重新打开、历史轮次与多轮追问

**Status:** ready-for-agent

**后端并行:** 可（mock 会话列表与历史足以驱动切换；真实并发取消在后端可用后联调）

**范围:** 会话条目选择、流式中止、视图清理、草稿丢弃、快速切换防串台

**预估:** 1h

- [x] 点击其他会话：先 abort 当前流，再清空旧 turns/sources，再加载目标历史
- [x] 切换后目标会话高亮更新，标题、轮次、来源面板都对应新会话
- [x] 切换过程中不出现旧会话正文或旧来源残留
- [x] 点击当前会话：不重新请求历史、不重建 turns
- [x] 草稿态点击已有会话：草稿丢弃，列表条目数不变，当前会话正常加载
- [x] 已有会话流式中点击其他会话：旧轮标记为停止或丢弃，不再继续追加增量
- [x] 从会话点击「新对话」：中止流式、清空视图、进入草稿，列表不变
- [x] 快速连续切换两次时只以最后一次选择为准，先到的历史响应不得覆盖后到的会话

## Comments

- 2026-03-11：新增 `useConversations.test.tsx`(3)、`useConversationHistory.test.tsx`(2)；修复切换期间主区误显示「新对话（草稿）」文案的问题，改为会话加载中显示「正在加载会话历史…」。
- UI 手工验证（dev server + 全站 mock）：创建 A/B 两个会话后点击 A，主区只显示 A 且 A 高亮；A 流式中立刻切 B，B 视图无 A 的半截回答；会话内点「新对话」进入「未保存」草稿空态且列表条数不变。
- 点击当前会话的「不重复加载」由 `handleSelect` 的同 id 短路保证；浏览器侧观察到内容与高亮无变化，但未注入网络观测以直接断言「零请求」。
- 快速切换的防串台由 `useConversationHistory` 的递增序号 + AbortController 在单测中覆盖（先发请求返回 `cancelled`，后发请求生效）。

# 03: 重新打开、历史轮次与多轮追问

**What to build:** 用户再次进入对话页时，自动选中最近更新的会话并加载历史：问题在右、回答在左，按 `roundId` 配对，引用可点击联动右侧面板；刷新页面或重新进入后讨论仍在。用户在同一会话继续提问时请求携带 `conversationId`，新轮追加在历史下方，历史参与后端生成；每轮结束后会话因最近更新回到「最近」首位。

**Blocked by:** 02 空态、新对话与首问端到端

**Status:** ready-for-agent

**后端并行:** 可（mock 维护多轮消息；真实历史装配在多轮后端 P3 完成后联调）

**范围:** 会话列表自动选中、历史消息接口、`roundId` 分组、历史渲染、后续追问、列表排序刷新

**预估:** 2h

- [ ] 列表非空时自动选中首项（后端按 `updateTime DESC, id DESC` 返回）并加载 `GET .../messages`
- [ ] 历史按 `roundId` 分组：每组恰好一条 `USER` + 一条 `ASSISTANT`，缺任一角色整组跳过
- [ ] 配对不依赖数组相邻下标，也不依赖 `createTime`；乱序或同秒数据仍正确
- [ ] `DONE` 历史渲染正文与【来源N】；点击来源时右侧面板切到该轮并高亮
- [ ] `sources: []` 的历史轮展示未召回提示；`FAILED` 展示错误文本；`STOPPED` 展示「已停止」
- [ ] 历史轮次不显示流式光标或「正在检索 / 回答生成中」
- [ ] 历史 `DONE` 复原 provider / 耗时 / 引用数；`FAILED / STOPPED` 的空值展示为「—」
- [ ] 列表或历史加载失败时显示服务端原因 + 重试，不展示上一会话残留
- [ ] 已有会话提问时请求体包含当前 `conversationId`，且与 active id 一致
- [ ] 新回答追加为独立轮次，旧轮正文、来源、状态不被覆盖
- [ ] 每轮 `done` 后静默刷新列表；该会话回到首位，当前高亮不丢；刷新失败不影响当前视图
- [ ] 流式期间输入框禁用，不能并发发起第二轮
- [ ] 离开 `/chat` 再进入（mock）或刷新页面（真实后端）后重新拉列表与历史，轮次配对、顺序、引用均正确；前端不把本地缓存当事实源
